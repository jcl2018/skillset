## Problem Statement

The play-along chart PDF reads wrong in nine places the owner named ("All 9"): a missing bar is squeezed, an estimated bar is not marked, bars carry no numbers, a section label has no start time, a section's last bars wrap onto the next section's line, the repeat count crowds the next chord, a one-page song wastes the page on small digits, a repeated section is drawn out in full, and empty header fields print "not shown".

## What Makes This Cool

A player at the music stand can find any bar by number, jump to a section by its time in the recording, see at a glance which bars are guesses and which are absent, and read a one-page song in big digits.

## Constraints

- Done lines are frozen (see chart-polish.md). Each fix shows in a rendered fixture chart, and a test proves it, seen failing first.
- The 2-page limit, the 9 pt floor for tab digits and the existing refusals hold. chart-format.json stays the one layout file: every new size and text lives there.
- Touches only skills/bass-tab, tests/bass-tab, .loop/regression.tsv and the Bass-tab and Tests wiki pages.

## Premises

1. Layout numbers and texts belong in chart-format.json alone; code reads them. Recommended default.
2. The fitting ladder may grow (rungs marked `pages: 1`, 11 and 12 pt) as well as shrink, and never goes under 9 pt. Recommended default.
3. Collapse-by-default means every ladder rung has `secref` on; `--expand-sections` turns it off, and `--collapse-sections` stays for old command lines. Recommended default.
4. A section's start time comes from META tempo only; a song with no tempo shows none. Recommended default.
5. A missing bar is as wide as the widest bar the song has, and never joins a repeat or a section reference. Recommended default.

(9) empty header fields and an all-"not shown" report left out: present. The nine polish rows pass when run one by one; done line 3's land lane was not run here.

Gap (Codex, confirmed by reading the code): `collapse` in chartplan.py refuses to fold a repeat across a missing bar, but not across an estimated bar, and `sections_identical` ignores estimates too. An estimated bar that is note-for-note equal to its neighbour is drawn once inside an `x2` repeat, so its estimate sign (fix 2) is lost; the same holds when a whole section collapses to a reference line. Remedy, a few lines in the same two functions: treat a bar listed in REPORT estimates like a missing bar. Committed behavior: an estimated bar is never part of a repeat run, so a run is split around it (bars before and after may still repeat on their own, each with its own count); a section that contains an estimated bar never collapses to a reference line and is drawn out; a section whose only difference from an earlier one is an estimate is therefore drawn out too. The longer chart goes through the same fitting ladder; if it no longer fits 2 pages at 9 pt, the existing refusal line names the song, as for any song that does not fit (done line 2 unchanged). A tenth polish row proves it, seen failing first, under done line 1. This is a code fix inside the goal, not a new decision.
