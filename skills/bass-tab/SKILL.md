# bass-tab

Turns what a source actually shows into a song data file, then renders a compact bass tab (`.tab`) and a
print-ready PDF in one fixed format. Needs `python3` only (Pillow is optional, for non-Latin titles).
Scripts live in `scripts/` next to this file; run them from this skill's folder or give full paths.

## The song file

One song, one directory, three files:

```
<slug>/
  <slug>.py     the source of truth: structured data, hand-editable (start from templates/song-template.py)
  <slug>.tab    generated by scripts/tabgen.py
  <slug>.pdf    generated by scripts/tab2pdf.py
```

`<slug>.py` supplies `META` / `BARS` / `SECTIONS` / `CHORDS` / `LYRICS`. **A repeated figure is written
ONCE and stamped wherever it is played**, so a correction reaches every copy. Never expand a repeat into
independent copies.

`LYRICS` is the user's row. Never write into it or fill it from a source (screenshot, web, memory). Leave
`LYRICS = {}` and say it is theirs to fill. It prints verbatim and survives every regeneration.

## Render

```
python3 scripts/tabgen.py <slug>/<slug>.py <slug>/<slug>.tab --bars <1 if META slots == 16 else 3> --cut compact
python3 scripts/tab2pdf.py <slug>/<slug>.tab -o <slug>/<slug>.pdf [--paper a4|letter]
```

Report pages and font size. **`--cut compact` is the sheet.** It is the only cut that carries the repeat
notation (a collapsed figure labelled `A-B  xN` in the text, drawn as repeat barlines in the PDF).
`tabgen.py` defaults to `full`, which prints every bar and adds a beat-ruler row the format does not list,
so a render without the flag does not conform. `--cut full` is a debugging view, never the deliverable.
Give both outputs full paths; a bare filename writes to the current directory.

The format: header lines (title, artist, key, tempo, time, tuning, source, legend), then per section a
`[Name - bars a-b . m:ss]` heading, a chord row, a bar-number row, a rhythm row `R|`, and four string rows
`G D A E`; then caveats, then a `[Checked]` block. Stave lines are pinned at 77 characters so every song
prints at the same scale; if a line is longer, use fewer bars per system.

## Making a song file from sources

Follow this literally; it is the point of the skill.

1. **Take only what a source actually shows.** A screenshot or PDF of a tab can be read. A link to a
   recording cannot: you cannot hear audio. From a song URL take the title, tempo and section names if
   printed, nothing else. Never supply a bar from memory of the song. A visible gap beats a bar that looks
   right and is not.
2. **Bass track only.** If a source shows several instruments, take the bass and say which track. Two bass
   tracks, or bass doubled: ask, do not pick.
3. **Cross-check every repeat, and encode it once.** Read each occurrence and compare. Agreement is the
   strongest verification available; disagreement means at least one reading is wrong. Occurrences agree:
   encode once. They disagree: say so, give the count each way, mark the reading an estimate. A bar with no
   repeat anywhere cannot be cross-checked; say that on the sheet.
4. **Never assert what you have not checked.** Claims like "same as bars A-B" are generated from the data,
   not typed. Section bar ranges are computed from boundaries.
5. **Structure, chords, tempo.** Fill `SECTIONS` with the source's own labels. Give each bar its `CHORDS`
   entry: the chord fixes which string a fret is on (fret 7 is B on the E string, E on the A string), so
   `tabgen.py` derives the string and raises on a fret/chord pair that agree on no string. Put the tempo in
   `META`; section timestamps are computed from it.
6. **Report what you did not do.** Which bars are missing, which are estimates, which source gave what. End
   every transcription with that, not with a clean bill of health.

Rhythm read by eye and frets never measured are the known weak points; say so in `CAVEATS`.

## Suggestions

After a transcription or on request, offer three kinds, clearly separated from the transcription:
**practice** (what to drill first), **musical** (what the progression is doing), and **arrangement** (a
simplification or addition). An arrangement suggestion is your invention; never let it read as what the
source says.
