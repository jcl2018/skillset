## Workflow loop

Generated by workflow-setup (`agents.py wire`); edit outside this block. Claude Code reads it in CLAUDE.md and Codex in AGENTS.md, so both run the same loop the same way.

- Read `.loop/START.md` first: how the loop fits together, every feature and how to use it, every setting.
- Run a command by asking for `<skill> <command>`. Each skill's Command map, in its SKILL.md, names the exact `python3 scripts/...` command, run from that skill's folder.
- A merge conflict in this block or in `.loop/START.md`: take either side, run `entry.py write`, commit.

Skills:

- `workflow-delivery`: Takes one sentence to a pull request by running your own idea, plan, review, test and ship skills unattended, in a background agent, with frozen done lines around them and review as the only gate.
- `workflow-docs`: Keeps a repo's wiki pages in the repo, finds pages that have gone stale, and publishes them to its GitHub wiki without touching pages it didn't write.
- `workflow-health`: Checks a repo against its own PRDs.
- `workflow-monitoring`: One session governs and the others build.
- `workflow-regression`: Keeps a repo's regression tests visible and enforced.
- `workflow-release`: Releases a goal once it has a pull request.
- `workflow-setup`: Surveys a git repo and writes its .loop/ config on a branch, so the delivery, monitoring and release skills can run there.
